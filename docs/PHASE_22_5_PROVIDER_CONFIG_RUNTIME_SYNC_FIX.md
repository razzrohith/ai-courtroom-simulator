# Phase 22.5 – Provider Configuration Runtime Sync Fix

## Bugs Fixed
- **Dynamic model loading**: OpenRouter models only appeared after closing/reopening the Provider Configuration modal.
- **API key save handling**: Saving an OpenRouter API key did not trigger model loading, leaving the model dropdown empty until a manual refresh.
- **Refresh button**: "Refresh" button re‑loaded models but only after the modal had been reopened.
- **Save Configuration button**: Remained disabled after making provider/model changes in some edge cases.
- **AgentPanel status**: Showed "Not connected" even when a provider was properly configured because the runtime status was not refreshed.

## Root Cause
1. `loadModelsForProvider` was defined as a `useCallback` hook, causing it to be **hoisted after its usage** in `handleSaveApiKey` and the provider `onChange` handler – resulting in a runtime `ReferenceError` and preventing the automatic model load.
2. The API‑key save handler (`handleSaveApiKey`) did not call `loadModelsForProvider`, so the model list stayed stale.
3. Provider selection `onChange` only updated the config without triggering a model load for the newly selected provider.
4. `Save Configuration` button relied on `isDirty`, which was not set when only the API key changed.
5. `AgentPanel` displayed a warning badge based on `modelInfo.isPlaceholder` but never refreshed the runtime status after configuration changes.

## Files Changed
- `src/components/ProviderSettings.tsx`
  - Refactored `loadModelsForProvider` into a plain async function (hoisting safe).
  - Added call to `loadModelsForProvider` after saving an API key.
  - Added call to `loadModelsForProvider` after changing a provider in the dropdown.
  - Updated dependency array of `handleSaveApiKey`.
- `docs/PHASE_22_5_PROVIDER_CONFIG_RUNTIME_SYNC_FIX.md` (new)

## Remaining Limitations
- No automated unit tests for the provider workflow; manual QA covers the main paths.
- Error handling for fetch failures only shows a generic message; could be improved with more granular feedback.
- The runtime status panel only polls on modal open and refresh; a real‑time websocket update would be more responsive.
